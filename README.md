# FurkVPN для Windows

Клиент FurkVPN для Windows 10 и 11 (x64) на Xray-core. Функции те же, что в Android-приложении
([furkvpn-android](https://github.com/foxodever/furkvpn-android)), вид тоже: Material 3, его цвета и шрифт Google Sans.
Сервер общий: furkapp.net (API `/api/v1/config`, страница `/import`, загрузки).

```
cmd/furkvpn/           FurkVPN.exe — окно (Wails + WebView2) и значок в трее, работает от имени пользователя
cmd/furkvpn-service/   FurkVPNService.exe — служба Windows (LocalSystem): ядро Xray, TUN, вся логика
internal/              общий код: ключи, подписка, маршрутизация, белые списки, сборка конфига Xray, движок службы
frontend/              интерфейс (Svelte 5, TypeScript), встраивается в FurkVPN.exe
installer/             установщик (NSIS)
build/                 сборка, значки, ресурсы Windows, выкладка
cmd/devbridge/         разработка: интерфейс в обычном браузере поверх службы, запущенной на Linux
```

## Как это устроено

- **Две программы.** VPN требует прав администратора (адаптер, маршруты, фильтры Windows), поэтому всё, что с ним
  связано, делает служба `FurkVPN`. Её ставит установщик, и она запускается вместе с Windows. Окно (`FurkVPN.exe`)
  работает без прав администратора, поэтому UAC при запуске не спрашивает. Они общаются по именованному каналу
  `\\.\pipe\FurkVPN`: JSON-строки, запросы-ответы и события. Служба отдаёт состояние частями (`vpn`, `traffic`,
  `subscription`, `routing`…) и присылает только те, что изменились. Права на канал: система и администраторы —
  полные, вошедшие в систему пользователи — чтение и запись, но не создание экземпляров канала. Окно проверяет, что
  канал создан системой (владелец SYSTEM или «Администраторы», сеанс 0): программа без прав не может выдать себя за
  службу, пока та остановлена.
- **Ядро** — Xray-core v26.9.30. Android-приложение в 1.4.1 вернулось на v26.9.9 (на v26.9.30 автовыбор работал хуже,
  причина не найдена), но для Windows v26.9.9 не подходит: в ней нет фильтров утечек (`autoSystemWfpBlockLeak`) и
  пропуска DNS-серверов адаптера для собственных запросов Xray. Вероятная причина плохого автовыбора исправлена в
  1.2.0 (см. «Общее состояние Xray»). Используется встроенный TUN-вход Xray для
  Windows (Wintun): адаптер `FurkVPN` (172.19.0.1/30, fdfe:dcba:9876::1/126), маршруты 0.0.0.0/0 и ::/0
  (`autoSystemRoutingTable`). Собственные соединения Xray привязаны к физическому интерфейсу
  (`autoOutboundsInterface`), иначе они бы зациклились в туннеле. Фильтры Windows Filtering Platform
  (`autoSystemWfpBlockLeak: ["dns"]`) не дают DNS-запросам уйти мимо туннеля: Windows шлёт их на DNS-серверы всех
  адаптеров, а программы ходят к роутеру по маршруту локальной сети. DNS-сервер адаптера — 172.19.0.2, запросы на
  порт 53 отвечает DNS-модуль Xray, как на Android (по TCP, `serveStale`, только IPv4).
- **Конфиг** берётся из подписки Remnawave (`<ключ>/json`) как есть: правила, балансировщики автовыбора, burstObservatory.
  Меняется только вход (TUN и раздача вместо socks/http шаблона). Секции, которые могли бы открыть порт или писать
  файлы от имени SYSTEM (`api`, `metrics`, `reverse`, логи), выбрасываются.
- **Программы без VPN** — правило маршрутизации Xray `process` (по имени exe). Оно стоит раньше остальных, так что
  на эти программы не действуют ни правила сервера, ни свои. Рекомендуемые исключения для Windows приходят из API
  отдельным списком: `/opt/furkapp/config/config.json` → `app.windows.defaultExcludedApps`, имена процессов
  (`["chrome.exe", "Telegram.exe"]`; `.exe` можно не писать, регистр не важен). Сервер подхватывает файл сам, приложения —
  при запуске (если загружали больше часа назад), раз в 6 часов и по «Проверить обновления». На Android список `defaultExcludedApps` состоит из пакетов. Список программ на
  экране собирается из ярлыков меню «Пуск» и запущенных программ, с их значками; любую программу можно выбрать файлом .exe.
- **Расширенные настройки** (для тех, кому надо). Режим TUN: MTU (1280–9000, по умолчанию 1500), IPv6 через VPN
  (выключен — у адаптера нет IPv6 и маршрута `::/0`, а IPv6 мимо туннеля закрыт фильтром `misconfigtun`, программы
  переходят на IPv4), защита от утечек DNS (`autoSystemWfpBlockLeak: ["dns"]`; без неё DNS-серверы роутера и рабочей
  сети снова доступны). Режим TUN можно выключить: адаптера нет, VPN — прокси на 127.0.0.1:10808 (SOCKS5 и HTTP на
  одном порту, если занят — следующий свободный). «Системный прокси» (по умолчанию включён) прописывает его в настройки
  прокси Windows текущего пользователя, пока VPN включён. Это делает окно, служба не может менять настройки
  пользователя. Прежние настройки окно запоминает в `ui.json` и возвращает при отключении, выходе, следующем запуске
  после сбоя; установщик и удаление тоже их возвращают (`FurkVPN.exe --restore-proxy`). Программы без VPN и журнал
  подключений работают и через прокси. Изменения применяются сразу, VPN переподключается сам.
- **Белые списки** — как на Android: проверка сайтов из `whitelist.*` мимо VPN (сокеты привязаны к физическому
  интерфейсу), при открытом окне, смене сети и раз в 5 минут при подключённом VPN. Автопереключение на
  «Автовыбор LTE» и обратно работает по тем же правилам.
- **Автовыбор**: перезапуск ядра при смене сети (в том числе когда та же сеть пропала и вернулась), раз в 10 секунд
  проверка серверов, которые нёс автовыбор, после сна дольше 5 минут — перепроверка, запасной сервер (`fallbackTag`) —
  всё как в Android 1.3–1.5.
- **Пинг** (как в Android 1.5.0) — время подключения к серверу и запроса к сайту проверки через него: адрес из
  JSON-конфига (`burstObservatory.pingConfig.destination` или `observatory.probeURL`), если его нет — `delayTestUrl` из
  API. Поиск адреса сервера по имени в пинг не входит: имена резолвятся заранее (через DNS-сервер конфига, у которого
  этот домен в списке, — в шаблоне это 77.88.8.8, — иначе через DNS Windows; пока VPN включён, эти запросы привязаны к
  физическому интерфейсу, как собственные соединения Xray), и тестовое ядро подключается к IP. Имя сервера остаётся
  SNI и Host, если они не заданы. «Автовыбор» тоже получает пинг: запрос идёт через его маршрутизацию и балансировщик.
  Правый щелчок по серверу или «Автовыбору» проверяет только его. До 1.2.0 серверы с доменом показывали ~4 с.
- **Общее состояние Xray**: DNS-клиент и менеджер исходящих, через которые ядро подключается к серверам по имени, у
  Xray одни на процесс, и каждое новое ядро забирает их себе. Тестовое ядро пинга оставляло работающему VPN свой, уже
  закрытый DNS: новые подключения к серверам с доменом ждали 4 с, а проверки автовыбора (3 с) считали их упавшими.
  Теперь после создания тестового ядра это состояние возвращается работающему (`TestDelayTestLeavesTheRunningInstanceItsDNS`).
- **Домены серверов вне списка DNS**: если у DNS-сервера конфига есть список доменов серверов, а какого-то сервера в
  нём нет, служба дописывает его туда (при подключении и для пинга), иначе его имя резолвилось бы через прокси.
- **Продлить / Купить тариф** в карточке подписки: «Продлить», когда до конца тарифа меньше 2 дней или он закончился,
  на бесплатном тарифе — «Купить тариф». Обе открывают `https://<site.domain>/renewal?sub=<id подписки>`.
- **Прокси для Telegram** — кнопка под «Наш сайт / Наш бот / Поддержка» открывает список из API (`telegramProxies`);
  щелчок отдаёт ссылку Telegram (`tg://`) или браузеру (`https://t.me/…`). Пока список пуст, кнопки нет.
- **Раздача интернета**: HTTP-прокси и SOCKS5 на 0.0.0.0 (8080/1080 или следующие свободные), только для адресов
  локальных сетей. На время раздачи служба добавляет правило брандмауэра Windows для своих портов.
- **Журнал подключений**: программа определяется по таблицам TCP/UDP Windows (как правило `process` в Xray), её
  название — из свойств exe. Программы без VPN тоже видны, с пометкой «Напрямую».
- **Ссылки и файлы**: установщик регистрирует протокол `furkvpn://`. Страница furkapp.net/import на компьютере
  открывает `furkvpn://import?url=…`, так что вход через бота и через сайт работает без изменений на сервере.
  Файлы настроек (`.json`) открываются через «Открыть с помощью → FurkVPN» или перетаскиванием в окно.
  Файл маршрутизации тот же, что у Android (`furkvpn-routing`). Список программ — свой тип (`furkvpn-windows-apps`).
- **Трей**: серый значок — не подключено, оранжевый — подключение, зелёный — подключено. Щелчок открывает окно, в
  меню «Подключиться/Отключиться», «Открыть FurkVPN», «Выход» (отключает VPN). Закрытие окна прячет его в трей.
- **Автозапуск**: при первом запуске окно прописывается в автозагрузку пользователя (`--tray`, без окна), это
  выключается в настройках. «Подключаться при включении компьютера» включает VPN службой, ещё до входа в Windows.
- **Обновления**: блок `windows.update` в config.json (`versionCode`, `versionName`, `url`, `sha256`, `changelog`).
  Служба скачивает установщик в `C:\ProgramData\FurkVPN Updates` (писать туда может только система),
  проверяет SHA-256. Окно запускает его с `/S /UPDATE`, Windows спрашивает разрешение (UAC). Установщик тихо
  ставит новую версию и снова запускает окно; если VPN был включён, служба включает его обратно.
- **Данные**: `C:\ProgramData\FurkVPN` (ключ, подписка, настройки; доступ только у системы и администраторов),
  журналы службы — `C:\ProgramData\FurkVPN\logs` (без посещённых адресов). Окно хранит только размер и
  флажки в `%APPDATA%\FurkVPN\ui.json`, журнал окна — `%LOCALAPPDATA%\FurkVPN\ui.log`.
- **Флаги стран**: Windows не рисует эмодзи флагов (вместо 🇳🇱 показывает «NL»), поэтому в интерфейс встроен шрифт
  Twemoji Country Flags. Остальные эмодзи берутся из системного шрифта.

## Сборка (на Linux)

Нужны Go (`/usr/local/go`), Node.js, `go-winres` (`go install github.com/tc-hib/go-winres@latest`), NSIS (`makensis`),
`osslsigncode`, `curl`.

```bash
build/build.sh        # → dist/FurkVPN-Setup-<версия>.exe (и FurkVPN.exe, FurkVPNService.exe отдельно)
go test ./...         # тесты: ключи, подписка, маршрутизация, белые списки, конфиг Xray, пинг, движок службы, IPC
go run ./cmd/pingtest -sub <подписка.json>   # пинг всех серверов подписки, как кнопка пинга
cd frontend && npm run check   # проверка типов интерфейса
```

Версия — файлы `VERSION` (сейчас 1.2.0) и `VERSIONCODE` (растёт с каждым выпуском, по нему приложение понимает, что
вышло обновление). Wintun 0.14.1 скачивается с wintun.net и сверяется по SHA-256, загрузчик WebView2 — с сайта
Microsoft, сверяется подпись. Сертификата подписи кода пока нет: SmartScreen при первом запуске установщика
покажет «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае», а UAC — «неизвестный издатель».

### Интерфейс в браузере

Служба собирается и на Linux: там режим TUN всегда выключен — прокси на 127.0.0.1:10808, сеть сервера не
трогается. `cmd/devbridge` отдаёт интерфейс в браузер и передаёт запросы службе.

```bash
go build -o /tmp/furkvpn-dev-service ./cmd/furkvpn-service && FURKVPN_DATA=/tmp/furkvpn-data /tmp/furkvpn-dev-service &
(cd frontend && npm run build) && go run ./cmd/devbridge -dist frontend/dist   # http://127.0.0.1:34115
```

## Выпуск

```bash
build/build.sh
build/publish.sh "Что нового"   # на сервере furkapp.net: установщик в /download, блок windows.update в config.json
```

furkapp.net открывается через промежуточный сервер, он отдаёт `/download/` со своего диска, а если файла там нет,
берёт его с основного. Новые установщики (`FurkVPN-Setup-<версия>.exe`, `FurkVPN-Setup.exe`) стоит скопировать и туда,
как APK.

Для теста обновлений служба читает переменную `FURKVPN_API` (значение `Environment` службы в реестре) — другой
адрес API вместо furkapp.net. С ней разрешены установщики по http.

## Проверено (виртуальная Windows 11 24H2, русская)

- установка с загрузкой WebView2 (в образе его не было), установка поверх, удаление;
- вход по ссылке `furkvpn://import?url=…` (как со страницы furkapp.net/import) при уже открытом окне;
- подключение: адаптер FurkVPN, маршрут по умолчанию через него, внешний IP — IP серверов автовыбора;
- DNS: запрос напрямую к DNS-серверу роутера не проходит, к 8.8.8.8 отвечает Xray;
- программа без VPN (curl.exe) выходит со своим IP, остальные — через VPN, туннель пересобирается сам;
- раздача: HTTP и SOCKS5 по адресу в локальной сети работают, с 127.0.0.1 отсекаются, правило брандмауэра есть;
- журнал подключений с названиями программ;
- белые списки (Google закрыт через hosts): переключение на «Автовыбор LTE», пинг только обходных, возврат на Wi-Fi;
- адаптер выключен и включён: ядро перезапустилось, интернет через VPN вернулся;
- перезагрузка: служба подключилась сама (автоподключение), окно запустилось в трей;
- трей: цвет по состоянию, меню, подключение из меню, открытие окна;
- обновление 1.0.0 → 1.0.1 через тестовый API: скачивание, UAC, тихая установка, VPN снова включён, окно открылось;
- расширенные настройки: MTU 1400 у адаптера; без IPv6 нет адреса и маршрута `::/0`, IPv6-соединение мимо туннеля
  не проходит; без защиты DNS роутер отвечает напрямую; режим прокси: адаптера нет, системный прокси пользователя
  указывает на 127.0.0.1:10808, программы с системным прокси выходят через VPN, curl — напрямую; прежние настройки
  (с «Определять параметры автоматически») возвращаются при отключении, выключении системного прокси, запуске после
  аварийного завершения и по `--restore-proxy`; сброс возвращает режим TUN.
